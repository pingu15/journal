# Journal

A premium, minimal, editorial journaling app. Native iOS, Swift + SwiftUI, **iPhone only**.

## Design direction
- **Style:** minimal / editorial. Lots of whitespace, restrained color, no ornament. Type: serif (New York via `design: .serif`) for page titles, numbers and section-level display text; **sans (SF) for entry text** — the editor (`MarkdownStyler`, `UIFont.sans`), entry titles/excerpts in lists (`Typography.entryTitle`/`entryExcerpt`) — and for sheet/popup titles (`Theme.applyNavigationBarAppearance`).
- **Palette:** https://colorhunt.co/palette/3434348e8b82e9dcbef3f3f3
  | Token | Hex | Role |
  |---|---|---|
  | ink | `#343434` | Primary text (light) |
  | stone | `#8E8B82` | Secondary text, metadata, hairlines, Markdown syntax |
  | sand | `#D4B48C` | The single accent — button fills, highlights (always white text and icons on top, `Theme.onAccent`) |
  | paper | `#F3F3F3` | Background (light) / primary text (dark) |
  | night | `#121212` | Background (dark) — deliberately deeper than ink (not from the palette link) |
- Use semantic tokens from `Journal/Design/Theme.swift` (`Theme` for SwiftUI, `UITheme` for UIKit, `Typography`, `Spacing`) — never hardcode colors, fonts, or spacing in views.
- Titles: every tab applies `.pageTitle(_:isHidden:)` (`PageTitle` in `Design/Components.swift`) to its scroll view: the journal's name and year span (`LargePageTitle`, white on a sand band that runs up behind the bar) stay fixed, and the page's content scrolls in a card with rounded top corners below it. Every tab shows the journal name — only Recently Deleted passes its own title (no year span). The bar has no title (an empty principal item keeps the system from drawing one); it has a sand background with `toolbarColorScheme(.dark)` so its buttons are white in both modes (the status bar picks its own color from the sand — white on this shade), and `ExpandingSearchBar` is drawn dark too (its text field keeps the app's scheme, so the keyboard matches).
- Home: the title hides while searching so results start under the bar. Month / "On this day" labels are plain rows (`SectionLabel`), not section headers, so they never pin under the bar. Row separators all start at one point (`EntriesView.separatorInset`, via `.alignmentGuide(.listRowSeparatorLeading)`) and the month labels start where they do; rows and their separators end the same distance in from the right. Search: the top-left button hands off to `ExpandingSearchBar`, drawn as an overlay on the bar row (a field inside a toolbar item can't span the bar — iOS collapses it into a ⋯ overflow menu) that grows sideways out of the button; while searching the bar has no buttons and the title row is hidden. Trailing: filter + `SettingsButton`.
- Every tab has `SettingsButton` (gear → Settings sheet) at the trailing edge. Calendar: Today (`<day>.square`) + settings.
- Tab bar is icons only (`TabIcon` keeps the name as the accessibility label). It's hidden while an entry is open by the tab's NavigationStack (`.toolbar(path.isEmpty ? .visible : .hidden, for: .tabBar)`), not by the editor: a pushed view's own setting only lifts after its pop animation, so the bar came back late.
- Journal name: `@AppStorage(JournalName.storageKey)`, default "Journal", editable in Settings; shown as the home title and on the lock screen. Use `JournalName.display(_:)` (empty → default).
- New entries: round sand `NewEntryButton` floating bottom-right of the Journal tab (writes for today); the Calendar has none — its day sheet's ✎ writes for that day.
- Appearance is applied by setting `overrideUserInterfaceStyle` on every window (`Appearance.apply`), not `.preferredColorScheme`, so open sheets and the lock window switch together.
- Empty-state and explanatory notes ("Nothing written on this day.", "Deleted entries stay here…", empty-tab descriptions, "No location set") all use `Typography.note` (footnote sans) in secondary text.
- Stone on paper is low contrast: use it only for secondary/meta text, never for body copy.
- Always support Dynamic Type and dark mode.

## Stack
- iOS 18.0+, Swift 6, default actor isolation = MainActor.
- SwiftData for persistence. Keep models CloudKit-compatible (defaults on every property, no `@Attribute(.unique)`, relationships optional) — iCloud sync is planned.
- LocalAuthentication for the optional Face ID lock (`Services/AppLock.swift`). The lock screen lives in its own `UIWindow` above everything (`PrivacyShield`) so sheets and full-screen covers are hidden too; Face ID is only requested once the scene is `.active`.
- WeatherKit (`Services/WeatherFetcher.swift`) — signed with team `L3957C4ZBL`, WeatherKit enabled on the App ID (works in the Simulator too). If requests fail with `WDSJWTAuthenticatorServiceListener.Errors error 2`, the build isn't carrying the team/entitlement. Weather is fetched when a place is set or changed, when the date changes, and when an entry with a place but no weather opens. Entitlement is in `Journal.entitlements`. **Apple's WeatherKit attribution was removed from Settings at the user's request — it must be shown somewhere (e.g. the editor header) before App Store submission.**
- CoreLocation + MapKit for places (`Services/LocationService.swift`).
- No third-party dependencies, no analytics.

## Features
- **Journal tab:** "On this day" section (same `EntryRow`, day + year) above month-grouped entries; rows are plain buttons (no disclosure chevrons). Search ("Search by text, date, or tag") via `Entry.matches`: text/tags/place by substring (image tokens excluded), dates by whole token ("Oct 6" ≠ Oct 16). Filter = All Entries | Recently Deleted (soft delete via `deletedAt`, purged after 30 days on launch). No summary line.
- **Editor:** `Entry.text` is **Markdown**, but the editor shows formatted text with no visible syntax (no `#`, `**`, `>`). `MarkdownDocument` (`Views/Editor/MarkdownStyling.swift`) converts Markdown ⇄ attributed text; semantic attributes (`.inlineStyle`, `.linkURL`, `.blockStyle`) are the source of truth and `MarkdownStyler` derives fonts/colors from them. Lists keep a visible marker (`•`, `☐`, `☑︎`, or the number) that serializes back to `- `, `- [ ] `, `- [x] `. Photos are `![](image:<Attachment.identifier>)` tokens rendered as `ImageAttachment`s; `---` is a `DividerAttachment`. Formatting comes **only** from the toolbar: typed `#`, `**`, `> ` etc. stay literal text — the serializer backslash-escapes any literal character that would otherwise read back as syntax (only where it could: `5 * 3` and `snake_case` stay as typed), and `Markdown.plainText` unescapes. Typing `#tag` makes a tag (styled stone). The header (date/time, place + weather icon and temperature) is a hosted SwiftUI view inside the text view, so the whole page scrolls together; tapping the date opens `DateEditSheet`, sized to fit the calendar and time row. The editor's back button has no long-press menu (`hidesBackButtonMenu()`), so it never shows the journal name. Entries open with a zoom out of their row and the back button zooms back into it, but an edge swipe slides the page away at full size: `slidesBackOnEdgeSwipe(onOpened:beforeZoomBack:)` (applied in `EntriesView`'s `navigationDestination`) clears the pushed controller's `preferredTransition` once it has appeared (the zoom's own edge pan shrinks the page) and sets a `navigationItem.backAction` that restores the zoom and pops on the next turn. The zoom hides its source row for as long as the entry is open and an edge swipe never un-hides it (changing the source's id doesn't either), so while the entry is open a copy of the row is overlaid on it (`releasedSource`) and shows behind a swiped page; `beforeZoomBack` removes the copy so the back button zooms into the real row. While editing, a sand checkmark to the right of the ⋯ (top right) ends editing. Its ⋯ menu's Share exports the entry as a PDF (`JournalExport.writePDF(of:)`: `JournalPDF` with no title page, named after the entry's title or date) through `ShareSheet`; the list's context-menu Share still shares plain text. Autocorrect and keyboard suggestions keep the replaced word's formatting (the coordinator carries its inline style and link over to the replacement). A new entry starts in the Title style (the first line is its title). Keyboard bar (`MarkdownToolbar`): a rounded glass capsule floating just above the keyboard (inset from the sides), large icons that scroll sideways when they don't fit: photo, text style popover (Title / Heading / Regular, each set in its editor font with the current one checked — a popover because menu items can't take custom fonts; the aA button itself never highlights), bold, italic, strike, quote, link (asks for a URL), divider — tools get a glass highlight when that style is on at the caret or across the selection (`MarkdownEditorController.activeInline/activeBlock`). Existing `code` spans still display but there's no button. Links have a faint underline; tapping one opens it when not editing (while editing, a tap places the caret). Return continues lists (ends them on an empty item), leaves a title/heading for body text, and leaves a quote on an empty line; tapping ☐ ticks it; tapping a photo opens the viewer. The entry's title (`Entry.title`, shown in list previews) is its first line **only if that line is in the Title style** (`# `); otherwise there's no title and the preview is all excerpt. A photo-only entry shows no stand-in text in lists (just its thumbnail and meta); only a truly blank one says "Empty entry". `#hashtags` = tags. Deleting a photo removes it on exit.
- **Cover image:** `Entry.coverImageID` (falls back to the first embedded photo) → `Entry.coverPhoto`. Set it from the photo viewer's ⋯ menu, which holds both "Set as Cover Image" (same label with a checkmark when it's already the cover) and Delete Photo (asks in an alert with Cancel — a confirmation dialog's glass took on the photo's colors; removes the token from the text via `MarkdownEditorController.removeImage`). The viewer's close and ⋯ buttons are dark glass circles; tapping the black around the photo also closes it, and so does swiping down at normal size (the photo follows the finger and the entry fades in behind — the cover has a clear `presentationBackground`). Photos pinch- and double-tap-zoom (`ZoomableImage`, a `UIScrollView`); its swipe-down pan only begins for a mostly-downward pan when not zoomed, so sideways paging and zoomed panning still work.
- **Calendar tab:** one long vertical scroll of months (`LazyVStack`, −120…+24 months, opening on this month via `scrollPosition(id:)`; Today scrolls back to it), each month's title (a `MetaLabel`, like the editor's date, with the year) (no band behind it) over rounded-square days with sans numbers, the title's row as far from the days on either side as the days are from each other — sand when written, or the cover photo of the day's earliest entry with one (`ThumbnailCache`). The weekday row sits above the scroll at the top of the card (not in its `safeAreaInset`, which made the opening position land this month's title under it). Tapping a day opens `DaySheet` (`Views/Calendar/DaySheet.swift`, medium/large detents, swipe down to close): the date with arrows to the day before/after, that day's entries (tapping one closes the sheet and opens the editor with a plain push; ✎ writes for that day unless it's in the future), then the photos taken that day from the photo library (`Services/PhotoLibrary.swift`: PhotoKit, read access requested from a button the first time, `NSPhotoLibraryUsageDescription`).
- **Insights tab:** words tile spanning the top, then streak / longest streak / entries / days written in a 2×2 grid, 18-week activity grid (written / not written — `Theme.activityFilled`/`activityEmpty`, no legend or summary line; tapping a day shows its date and word count), top tags (tapping one opens the Journal tab searching for it via `AppRouter.search(for:)` / `pendingSearch`).
- **Settings:** journal name, appearance (system/light/dark), daily reminder, "Add current location" (`LocationService.autoTagKey`; turning it on asks for location access and stays off if refused — the editor never prompts: a fresh entry dated today gets the current place and its weather on open, and if it's left with no text or photos the auto-added place is cleared so the entry is still discarded), Face ID lock, Export (button → Markdown or PDF dialog → share sheet). `JournalExport.write` builds the file; `JournalPDF` typesets a book-style PDF (title page, entries via TextKit with formatted Markdown and photos, page numbers, entries starting near a page foot move to the next page).
- **Location sheet** ("Set Location"): custom search field pre-filled with the current place, a non-interactive map as wide as the cards below it (camera set in `init` — the Map ignores changes made in `onAppear`) marking the place with a sand dot on a soft sand halo, then Current Location / Remove / place suggestions; sections are `Spacing.m` apart, like the search field and map.
- No favorites, no writing prompts, no mood (all removed deliberately).
- **App Shortcut:** "New entry in Journal" (`App/NewEntryIntent.swift`) via `AppRouter.shared`.

## Project layout
- `Journal.xcodeproj` uses a file-system-synchronized group: any file added under `Journal/` is in the target automatically — no need to edit `project.pbxproj`.
- `App` entry point, tabs, lock handling, router, intents · `Models` SwiftData models (`Entry`, `Attachment`) · `Design` theme tokens + shared components · `Views/<Feature>` screens · `Services` non-UI logic (Markdown helpers, stats, export, reminders, location, weather, image processing).
- Queries for live entries must filter `deletedAt == nil`. Use `entry.moveToTrash()` rather than `context.delete` for user-facing deletes.
- Blank entries are created eagerly on "New entry"; the editor deletes them on exit, and `Entry.deleteBlankEntries` sweeps leftovers on launch and when a navigation stack returns to root (skipping `AppRouter.openEntries`).
- Save explicitly (`try? context.save()`) after leaving the editor, destructive actions, and when the scene leaves `.active` — don't rely on autosave timing for a journal.
- Editor clipboard: copy/cut put **Markdown** (with photo tokens) on the pasteboard; paste parses Markdown (so formatting carries over) and rebuilds photos inline (`resolvePastedImage` copies photos from other entries, and duplicates get their own `Attachment`), images from other apps are imported, and photos can't be dragged. Pasted photos always get their own line.
- Live styling is incremental (`MarkdownStyler.style(_:in:)` restyles only edited paragraphs, tracked via `NSTextStorageDelegate`) — keep every styling rule line-local, and keep `MarkdownDocument` round-tripping (Markdown → editor → Markdown must reproduce stored entries exactly; formatting changes only touch attributes). Format toggles register their own undo (`editAttributes`); edits that insert attachments clear the undo stack. Rendered photos are cached by id (`ImageAttachment.cached`).
- `SystemPrompts.shared.during { … }` wraps any permission prompt (Face ID, location, notifications) so the privacy shield doesn't flash up while the scene is briefly inactive.
- Journal name is capped at `JournalName.maxLength` (40).
- Don't push onto a NavigationStack while `.searchable` is dismissing (the push gets dropped); `EntriesView.newEntry` closes search first.

## Debugging
- Launch with `-seedSampleData` (DEBUG only) to fill an empty store with ~4 months of entries:
  `xcrun simctl launch booted com.maxsun.journal -seedSampleData`
- Simulator Face ID: enroll with `xcrun simctl spawn booted notifyutil -s com.apple.BiometricKit.enrollmentChanged 1 && xcrun simctl spawn booted notifyutil -p com.apple.BiometricKit.enrollmentChanged`; pass a prompt with `xcrun simctl spawn booted notifyutil -p com.apple.BiometricKit_Sim.pearl.match` (`.nomatch` to fail).
- Simulated taps on iOS 26 switches need a ~0.2s press to register. Injected taps right after a launch, or very short ones, are often dropped by the simulator — use ~0.15s taps and don't read a missed first tap as an app bug.
- Launch with `-lockEnabled NO` to skip the Face ID lock for one run without changing the stored setting.
- Read the store directly: `sqlite3 "$(xcrun simctl get_app_container booted com.maxsun.journal data)/Library/Application Support/default.store" "select ZTEXT from ZENTRY"`.
